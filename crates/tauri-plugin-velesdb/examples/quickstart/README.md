# quickstart — the smallest complete app

Three files, dropped into a Tauri 2 project:

```text
src-tauri/src/main.rs                 <- register the plugin
src-tauri/capabilities/velesdb.json   <- unlock the commands
src/main.js                           <- call them
```

Copy them from this directory, keeping the same relative paths.

## 1. Add the dependency

```bash
cd src-tauri
cargo add tauri-plugin-velesdb
```

## 2. Copy the files

```bash
cp examples/quickstart/src-tauri/src/main.rs                 src-tauri/src/main.rs
mkdir -p src-tauri/capabilities
cp examples/quickstart/src-tauri/capabilities/velesdb.json   src-tauri/capabilities/velesdb.json
cp examples/quickstart/src/main.js                           src/main.js
cp examples/quickstart/index.html                            index.html
```

If your project already has a `main.rs`, add the single `.plugin(...)` line
rather than overwriting it.

## 3. Run

```bash
npm run tauri dev
```

## Expected output, in the webview console

```text
inserted: 2
{
  "results": [
    { "id": 1, "score": 1.0, "payload": { "title": "north" } },
    { "id": 2, "score": 0.0, "payload": { "title": "east" } }
  ],
  "timingMs": 0.42
}
```

**How to read it.** With the `cosine` metric the score is a similarity: `1.0`
means identical, `0.0` means orthogonal. Success is *`id: 1` ranked first with
a score close to `1.0`*. The last decimals and `timingMs` will differ on your
machine — that is normal.

A directory `./velesdb_data` now exists next to the running binary. That is
`init()`'s default, relative to the working directory — fine for prototyping,
wrong for a shipped app. See [`../production-config`](../production-config).

## If it failed instead

| Symptom | Cause | Fix |
|---|---|---|
| `invoke` rejects with a permission error before the plugin runs | the capability is missing, or `windows` does not list the calling window's label | check `src-tauri/capabilities/velesdb.json` and that your window is labelled `main` |
| `{ code: "VELES-002", message: "Collection 'demo' not found" }` | the search ran before the create succeeded | the example awaits each call in order; if you split them across handlers, keep that ordering |
| `{ code: "VELES-001" }` on `create_collection` | the collection already exists from a previous run | reuse it, or delete `./velesdb_data` |
| nothing at all in the console | the frontend module was never loaded | check that `index.html` includes `<script type="module" src="/src/main.js">` |

## About the capability file

Tauri 2 denies plugin commands by default. `"velesdb:default"` is the plugin's
generated permission set, covering every command it registers — the full list
is in [`permissions/autogenerated/reference.md`](../../permissions/autogenerated/reference.md).

For a tighter grant, replace `"velesdb:default"` with the individual
permissions you actually use, e.g.:

```json
"permissions": [
  "velesdb:allow-create-collection",
  "velesdb:allow-upsert",
  "velesdb:allow-search"
]
```

`"windows": ["main"]` scopes the grant to the window labelled `main`. A second
window with a different label gets nothing until you list it too.
