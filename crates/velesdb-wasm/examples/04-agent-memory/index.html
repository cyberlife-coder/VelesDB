VelesDB WASM — agent memory in the tab

MemoryService is the agent-memory wedge: store a fact, recall it by meaning, link facts to each other, then ask why a decision was reached and get the evidence subgraph back. No backend, no embedding endpoint — the offline HashEmbedder ships inside the module.

Two things to know before you build on this

  • It is in-memory only. There is no filesystem in WASM; a reload starts from an empty store. Persist what matters yourself.
  • Ids cross the boundary as decimal strings ("1", not 1 or 1n) — a plain number would lose precision above 253.

This is also the supported path in 4.0.0: SemanticMemory.query() throws Invalid search results on every call and must not be used.
